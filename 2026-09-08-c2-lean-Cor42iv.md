### The ring — the decision that mattered

Exponents in the two-assignment sum (`P - k`, `Q + k`) are unbounded integers, so the
ambient ring must be Laurent. I used the group algebra of `ℤ × ℤ`:

```lean
abbrev LaurentZ2 := AddMonoidAlgebra ℤ (ℤ × ℤ)
noncomputable def mono (a b : ℤ) : LaurentZ2 := AddMonoidAlgebra.single (a, b) 1
```

`MvPolynomial (Fin 2) ℤ` was never viable — `mono (P - k) Q` need not exist — and a uniform
monomial shift does not exist either, since `P, Q, k` range over all of `ℤ` in the core
lemma. The group algebra pays off twice: monomials are *definitionally* `Finsupp.single`, so
coefficient extraction is a `rfl` away (`twoAssign_eq_finsupp`), and the whole nonvanishing
argument is then one coefficient.

Faithfulness of the name `t^a s^b` is a theorem, not a comment: `mono_mul`
(`mono a b * mono c d = mono (a+c) (b+d)`), `mono_zero` (`mono 0 0 = 1`) — together, `mono`
is a monoid homomorphism from `(ℤ², +)` — and `mono_isUnit`.

### The core identity

```lean
theorem twoAssign_eq_zero_iff (P Q k : ℤ) :
    twoAssign P Q k = 0 ↔ k = 0 ∨ Q = P - k
```
where `twoAssign P Q k = mono (P-k) Q - mono P (Q+k) + mono (Q+k) P - mono Q (P-k)`.

*Reverse:* the two substitutions the paper checks implicitly.

*Forward — the content, and the step the printed proof asserts without argument.* Read the
coefficient of the single monomial `t^{P-k} s^Q`. It occurs with coefficient `1`, and the
three ways another term could cancel it are each excluded:

| cancelling term | requires | excluded by |
|---|---|---|
| `t^P s^{Q+k}` | `k = 0` | hypothesis |
| `t^Q s^{P-k}` | `Q = P - k` | hypothesis |
| `t^{Q+k} s^P` | `P = Q` **and** `Q + k = P - k` | together give `2k = 0`, so `k = 0` |

The third row is the one that makes this a real argument rather than a symbol count: it is
*not* excluded by either hypothesis directly, only by combining them. In Lean the whole
forward direction is `split_ifs at hco <;> omega` after the coefficient is unfolded.

Also proved, tying the object to the paper's derivation rather than leaving it as a
comment: `twoAssign_eq_add_swap` (the sum really is the two assignments `(b,c)` and `(c,b)`,
the second with heights swapped and crossing index negated — the paper's `k ↦ -k` of
`crossIndex_swap`) and `assignContrib_eq_mul` (the factorised form
`t^{P-k} s^Q (1 - (ts)^k)` that Cor. 4.2(iii) uses).

### The `e`-dependence

```lean
theorem twoAssign_eq_zero_of_le_two {e : ℕ} (he : 0 < e) (he2 : e ≤ 2) (M : Finset ℤ)
    (x y : ℤ) (hx : x ∈ M) (hxe : x + (e:ℤ) ∉ M) (hy : y ∈ M) (hye : y + (e:ℤ) ∉ M) :
    twoAssign (ribbonHeight e M x : ℤ) (ribbonHeight e M y : ℤ) (crossIndex e e x y) = 0
```

Two mechanisms, deliberately kept apart:

* `e = 1`: the open window `(y, y+1)` contains no integer, so both indicators of
  `crossIndex` vanish and `k = 0` outright (`ribbonHeight_one`).
* `e = 2`: a nonzero `k` **pins the geometry**. `k = 1` forces `x = y - 1`, and then
  legality evaluates both single-cell windows — `P = 1[y ∈ M] = 1` from `hy` and
  `Q = 1[x+2 ∈ M] = 0` from `hxe`, so `Q = P - k`. `k = -1` forces `x = y + 1` and the
  mirror argument gives `P = 0`, `Q = 1`. Otherwise `k = 0`.

```lean
theorem exists_twoAssign_ne_zero_three :
    ∃ (M : Finset ℤ) (x y : ℤ), x ∈ M ∧ x + ((3:ℕ):ℤ) ∉ M ∧ y ∈ M ∧ y + ((3:ℕ):ℤ) ∉ M
      ∧ TwoBead 3 3 x y
      ∧ twoAssign (ribbonHeight 3 M x : ℤ) (ribbonHeight 3 M y : ℤ) (crossIndex 3 3 x y) ≠ 0
```
Witness `M = Finset.Icc 6 8`, `b = 6`, `c = 8`: `P = 2`, `Q = 0`, `k = 1`, giving the
paper's `(t - s)(1 - st)` of Remark 4.3. So `e ≥ 3` is exactly the right hypothesis — the
`e ≤ 2` collapse is not an artefact of a coarse bound.

## What the type checker found that I had not

**`x ≠ y` is not needed for the `e ≤ 2` collapse.** I stated the lemma with the paper's
distinctness hypothesis and Lean's unused-variable linter flagged it. It is genuinely
redundant: the `k = +1` window forces `x < y` and the `k = -1` window forces `y < x`, so the
case split is already exhaustive. The hypothesis is now absent from the statement and its
absence is documented in the docstring. (One more instance of a pin that looked
load-bearing and was removable — → `a-fixed-parameter-can-be-the-whole-obstruction`.)

## Convention hygiene — what was deliberately *not* imported

`ribbonHeight` is used strictly as the window statistic `#{c ∈ M : b < c < b+e}` that
`TworowD4Kernel.AbacusRibbon` defines. Rick's identification of it with the leg length of
the `e`-ribbon (Day 180, `grandpa-rick/rick-research@616ea6e` §3; Littlewood's `e`-quotient
theorem, James–Kerber §2.7) is recorded in the module docstring and **used nowhere**: an
off-by-one in the ribbon-height convention would land squarely inside the range `[0, e-1]`
that the whole corollary is built on. Likewise Rick's `e = 2` parity argument is not
imported — the `e = 2` branch is derived from the window statistic and legality directly.
